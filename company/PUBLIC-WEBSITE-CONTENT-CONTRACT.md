# NexLabs Technology — Public Website Content Contract

**Status:** `CANONICAL_WO_014`

## Purpose

Define what public website content is allowed to say and what evidence it requires.

## Content classes

### COMPANY_FACT
Supported by canonical company state.

### PRODUCT_FACT
Supported by Product Factory/product repository evidence.

### RESEARCH_DIRECTION
An area being explored; not a breakthrough claim.

### DESIGN_PRINCIPLE
How NexLabs intends/builds systems; not externally validated performance.

### METRIC
Requires source, period, definition and proof state.

### EXTERNAL_PROOF
Customer/partner/award/certification/publication/press proof requiring independent verification and permission where relevant.

## Status-aware copy

Public product/project copy must disclose an appropriate state such as:
- research;
- prototype;
- private beta;
- public beta;
- active product;
- internal platform;
- open source;
- paused/retired.

Do not use a stronger status than evidence supports.

## Metrics

A visual reference may contain decorative/sample numbers, but they do not become publishable facts.

Metrics require:
- metric name;
- definition;
- value/range;
- period;
- source;
- state/confidence;
- last verification.

## Proof rule

If proof is missing:
- omit the claim;
- qualify it accurately;
- describe intent/method instead.

## CMS/content automation

Future automation may draft or update content only from governed sources.

It may not auto-publish material factual claims solely from model inference.

## Contact/data collection

Any future form/submission/analytics path requires separate privacy/security scope.

## Content expiry

Time-sensitive public facts should carry a verification/refresh rule so stale proof does not live forever.
