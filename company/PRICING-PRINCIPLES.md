# NexLabs Technology — Pricing Principles

**Status:** `CANONICAL_WO_004`

## 1. Price from value, not from guesswork

Pricing should be informed by:
- user problem severity;
- frequency of use;
- willingness to pay;
- alternatives;
- value created or cost avoided;
- cost-to-serve;
- retention;
- acquisition economics.

Infrastructure cost alone does not define price, but price must protect sustainable economics.

## 2. No universal NexLabs price

NexLabs serves multiple possible product categories. A low-cost consumer utility and an enterprise data product should not share one pricing philosophy merely for brand consistency.

Product-specific prices require product-specific evidence.

## 3. Prefer simple pricing first

Early pricing should minimize cognitive load.

Default preference:
- few tiers;
- clear feature/usage differences;
- visible limits;
- no hidden overage mechanics;
- understandable upgrade path.

## 4. Subscription where value recurs

Use subscriptions when customers repeatedly receive value. Do not force subscription onto naturally one-time value merely to manufacture MRR.

## 5. Usage pricing where usage drives cost or value

Use credits, metering or usage when:
- AI/compute/data cost changes substantially with consumption;
- customer value grows with consumption.

Avoid opaque token-like units when a simpler user-facing unit is possible.

## 6. Freemium and free tiers

Free access is a distribution tool, not a default.

Use only when one or more are true:
- marginal cost is controlled;
- free users create useful distribution/network effects;
- the upgrade path is observable;
- abuse/multi-account risk can be managed.

## 7. Trials

Prefer trials when users need to experience value before paying and the product can demonstrate that value in a bounded period or usage allowance.

## 8. Discounts

Discounts require a reason:
- annual prepayment;
- volume;
- launch experiment;
- strategic segment;
- contractual commitment.

Permanent discounting should not hide weak willingness to pay.

## 9. Lifetime deals

Not a default NexLabs model.

They may create upfront cash but can create perpetual service obligations against variable cloud/AI costs. Any lifetime offer requires explicit product-level approval and bounded entitlement.

## 10. Price changes

Price changes should preserve trust:
- explicit notice;
- clear effective date;
- documented migration/grandfathering policy when appropriate;
- no silent reduction of paid entitlement.

## 11. Evidence before scale

A price is not considered validated because users clicked a pricing page. Validation should eventually include paid conversion, retention, gross/contribution margin and qualitative customer evidence.
