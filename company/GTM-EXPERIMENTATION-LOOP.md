# NexLabs Technology — GTM Experimentation Loop

**Status:** `CANONICAL_WO_013`

## Loop

`HYPOTHESIS → SEGMENT → CHANNEL/OFFER → CAP → RUN → MEASURE → INTERPRET → DECIDE → UPDATE`

## Experiment contract

- `experiment_id`
- product;
- ICP/segment;
- hypothesis;
- channel;
- message/offer;
- budget/time/volume cap;
- success metric;
- guardrail metric;
- stop condition;
- attribution method;
- result;
- confidence;
- decision;
- learning.

## Good hypotheses

Specific enough to be wrong.

Example structure:
“For segment X with problem Y, channel Z/message A will create qualified activations at economics B.”

## Stop conditions

Stop/review when:
- spend cap reached;
- quality collapses;
- CAC/payback unacceptable;
- privacy/security issue appears;
- message attracts wrong segment;
- product cannot fulfill promise;
- statistically/practically sufficient evidence exists.

## Decisions

- scale;
- repeat;
- refine;
- switch channel;
- change segment;
- change message/offer;
- return to product validation;
- stop.

## Negative evidence

Failed experiments are retained when they improve future decisions.

## Learning path

Commercial learning must update:
- ICP confidence;
- positioning;
- channel strategy;
- pricing hypotheses;
- Product Factory;
- financial forecast.
